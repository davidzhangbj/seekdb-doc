# Fork 表

Fork Table 是 seekdb 提供的一项表级能力，用于基于源表在一致性快照时刻的数据视图，快速创建一张目标表副本。目标表与源表相互独立，后续读写互不影响，适用于数据版本分支、A/B 实验与沙箱验证、研发/训练数据准备等场景。本文档介绍 Fork Table 的能力与典型用法。关于语句语法、参数与完整限制，请参见文末的相关参考链接。

## 功能简介

在开发与迭代过程中，您可能需要基于同一份数据基线并行验证不同方案，例如数据修订、特征工程、索引与元数据策略调整等。如果采用传统方式全量拷贝表数据（例如 `CREATE TABLE ... AS SELECT ...` 或导出导入），在大表场景下可能带来较高的时间与资源成本。

Fork Table 的设计目标是在保证一致性语义的前提下，尽量复用已有的数据组织与存储结构，从而降低复制开销，让“创建数据分支”更轻量、更易用。

## 适用场景

Fork Table 适用于以下典型场景：

* **数据版本与分支管理**：围绕同一份基线数据派生多个分支版本，分别进行数据修订、特征更新或索引/元数据策略调整，并保留可追溯的版本关系。
* **A/B 实验与沙箱验证**：从生产表 Fork 出实验表，将实验性写入、索引重建与参数调优等操作放在实验表执行；实验失败可快速回滚，实验成功可进一步推广。
* **研发/训练数据准备**：快速获得“时间点快照”的可复现数据输入版本，降低数据准备成本。

## 工作机制

Fork Table 的关键语义包括：

* **快照一致性**：目标表反映的是源表在 Fork 时刻的一致性快照，之后源表的变更不会影响目标表。
* **读写隔离**：目标表与源表相互独立，对任一表的写入都不会影响另一方。
* **渐进可用**：目标表可在 Fork 完全结束前提供访问能力；后台过程不会改变对外的一致性语义与可用性。

## 使用限制及注意事项

* **与 DDL 互斥**：Fork 过程中源表和目标表与 DDL 操作互斥，建议避开同时间的 `CREATE/ALTER/DROP/RENAME` 等 DDL。
* **目标表需不存在**：如果目标表已存在，需要先删除目标表名。
* **索引与资源限制**：部分索引能力在当前版本可能受限；当源表包含 HNSW 向量索引时，Fork 可能带来额外内存压力，建议先小规模验证并做好监控。

## 示例：创建表副本并验证隔离

下面示例演示 Fork Table 的基本使用流程：创建表 → Fork → 验证表对象与数据一致性 → 验证写入隔离。

1. 创建源表并写入数据。

```sql
DROP TABLE IF EXISTS t1;
DROP TABLE IF EXISTS t1_fork;

CREATE TABLE t1 (
  c1 INT PRIMARY KEY,
  c2 INT
);
INSERT INTO t1 VALUES(1, 10);
```

2. 基于源表创建目标表副本。

```sql
FORK TABLE t1 TO t1_fork;
```

3. 验证目标表对象与数据一致性。

```sql
SHOW TABLES LIKE 't1%';
SHOW CREATE TABLE t1_fork;

SELECT COUNT(*) FROM t1;
SELECT COUNT(*) FROM t1_fork;
```

4. 验证写入隔离：写目标表不影响源表。

```sql
INSERT INTO t1_fork VALUES (2, 200);
SELECT * FROM t1_fork;
SELECT * FROM t1;  -- 源表仍只有 (1, 10)
```
