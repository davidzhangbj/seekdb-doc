# MySQL compatibility

This section describes the compatibility between SeekDB and native MySQL databases.

SeekDB supports most of the features and syntax of MySQL 5.7 and 8.0. However, due to differences in product architecture or low customer demand, some features are not supported. This section describes the differences between SeekDB and native MySQL databases in the following areas:

* Data types

* SQL syntax

* Procedural language

* System views

* Character sets

* Collations

* Functions and expressions

* Partitioning support

* Storage engines

* Optimizer

## Data types

SeekDB supports the following data types:

* Numeric types

  * Integer types: `BOOL`/`BOOLEAN`/`TINYINT`, `SMALLINT`, `MEDIUMINT`, `INT`/`INTEGER`, and `BIGINT`.

  * Fixed-point types: `DECIMAL` and `NUMERIC`.

  * Floating-point types: `FLOAT` and `DOUBLE`.

  * Bit-value type: `BIT`.

* Date and time types: `DATETIME`, `TIMESTAMP`, `DATE`, `TIME`, and `YEAR`.

* Character types: `CHAR`, `VARCHAR`, `BINARY`, and `VARBINARY`.

* Large object types: `TINYBLOB`, `BLOB`, `MEDIUMBLOB`, and `LONGBLOB`.

* Text types: `TINYTEXT`, `TEXT`, `MEDIUMTEXT`, `LONGTEXT`, and `STRING`.

* Enumeration type: `ENUM`.

* Set type: `SET`.

* JSON data type

* Spatial data type

* Efficiently compressed bitmap data type

* Array data type

* Vector data type

## SQL syntax

:::tab
tab Supported

**SELECT**

* Supports most query features, including single-table and multi-table queries, subqueries, inner joins, semi-joins, and outer joins, grouping, aggregation, and common data mining functions such as probability and linear regression.

* Supports set operations such as `UNION`, `UNION ALL`, `MINUS`, `EXCEPT`, and `INTERSECT` on the results of multiple `SELECT` queries.

* Supports the `EXPLAIN` syntax to view the execution plan.

**INSERT**

* Supports single-row and multi-row data insertion, and allows data to be inserted into a specified partition.

* Supports the `INSERT INTO ... SELECT ...` statement.

**UPDATE**

* Supports single-column and multi-column data updates.

* Supports data updates using subqueries.

* Supports set updates.

**DELETE**

* Supports single-table and multi-table data deletion.

**TRUNCATE**

* Supports emptying a specified table.

tab Not supported

**SELECT**

* Does not support the `SELECT ... FOR SHARE ...` syntax.

**TRUNCATE**

* Does not support operations during transaction processing or table locking.

:::

## Procedural language

SeekDB is compatible with most procedural language (PL) features of MySQL databases. The PL features supported by SeekDB are as follows:

* Data types
* Stored procedures
* User-defined functions
* Triggers
* Exception handling

In addition, SeekDB provides MySQL PL system packages, including `DBMS_RESOURCE_MANAGER`, `DBMS_STATS`, `DBMS_UDR`, `DBMS_XPLAN`, and `DBMS_WORKLOAD_REPOSITORY`.

For more information about PL features, see [PL Reference](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000002013356).

## System views

SeekDB implements most views in the `information_schema` and `mysql` internal databases. However, due to architectural differences, SeekDB does not guarantee that all views are implemented or that all columns in the views have the same meanings as in MySQL.

For more information about system views, see [System Views](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000002013001) in the [Reference Guide](url-placeholder-14866168-6d05-405d-8d60-370414339808).

## Functions

:::tab
tab Supported

The analysis (window) functions supported by SeekDB are a superset of those supported by MySQL. In other words, SeekDB supports all analysis (window) functions supported by MySQL.

tab Not supported

The following functions are not supported by SeekDB but are supported by MySQL:

* String functions: `LOAD_FILE()` and `MATCH()`.

* XML functions: `ExtractValue()` and `UpdateXML()`.

* Other functions: `MASTER_POS_WAIT()`.

:::

## Partitioning

The partitioning features supported by SeekDB are different from those supported by MySQL. The differences are as follows:

* SeekDB supports primary partitions and templated and non-templated subpartitions. MySQL does not support non-templated subpartitions.

* SeekDB supports Hash, Key, Range, Range Columns, List, and List Columns subpartitioning. MySQL supports only Hash and Key subpartitioning.

* SeekDB supports adding and dropping subpartitions. MySQL does not support adding and dropping subpartitions.

  <main id="notice" type='notice'>
    <h4>Notice</h4>
    <p>SeekDB does not support adding or dropping subpartitions of the Hash or Key type. </p>
  </main>

For more information about partitions, see [Overview of partitions](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000002015458).

## Storage engine

Unlike the InnoDB and MyISAM engines of MySQL, which are based on data blocks, SeekDB is based on the LSM-tree architecture.

## Optimizer

SeekDB supports some optimizer features of MySQL. For more information about the optimizer, see [SQL tuning](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000002013770).

:::tab
tab Supported

* View execution plans

  * The output columns include only `ID`, `OPERATOR`, `NAME`, `EST. ROWS`, and `COST`, and the details of the operators.

* View statistics

  * You can execute the `ANALYZE TABLE` statement to manually query histogram statistics about column values stored in the data dictionary tables.

  * You can automatically view table statistics and column statistics by using views.

* Query rewrite optimization

  * Supports outer join optimization.

  * Supports outer join simplification.

  * Supports block nested loop and bulk key access joins.

  * Supports condition filtering.

  * Supports constant folding optimization.

  * Supports `IS NULL` optimization (indexes do not store `NULL` values).

  * Supports `ORDER BY` optimization.

  * Supports `GROUP BY` optimization.

  * Supports `DISTINCT` elimination.

  * Supports `LIMIT` pushdown.

  * Supports window function optimization.

  * Supports avoiding full table scans.

  * Supports predicate pushdown.

* Optimizer hint mechanism

  * Supports join order optimizer hints.

  * Supports table-level optimizer hints.

  * Supports index-level optimizer hints.

  * Supports the `INDEX`, `FULL`, `ORDERED`, and `LEADING` hints.

* Supports parallel execution, including parallel queries, parallel replication, and parallel writes. SeekDB supports parallel operators, including parallel aggregation, parallel join, parallel grouping, and parallel sorting.

* Supports plan caching and prepared statements. MySQL does not support these features.

tab Not supported

* View execution plans

  * Does not support using the `SHOW WARNINGS` statement to display additional information.

:::
