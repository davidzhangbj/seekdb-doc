# Try full-text search

## Introduction to full-text indexing

A full-text index is a special type of index in a database that accelerates text data searches. It is particularly useful for handling queries involving a large number of text fields, such as articles, comments, and blogs. It supports fast keyword matching queries, allowing you to search for one or more words within a text and return relevant results. Full-text indexes are commonly used in search engines and text analysis systems to help businesses quickly locate key information and improve search efficiency.

In real-world business scenarios, full-text indexing can be applied to various situations such as system log analysis and user analysis. It enables efficient filtering and screening of data or high-quality relevance assessment. In the field of AI, seekdb employs a multi-retrieval architecture that combines sparse and dense vectors with full-text indexing. This approach enhances the efficiency and accuracy of retrieval in RAG systems within specialized knowledge domains.

The main features of full-text indexing include:

* Full-text search: By building a full-text index, you can comprehensively index entire documents or large segments of text, enabling more flexible and efficient searches.

* Quick lookup: Users can quickly search for matching text in the database based on input keywords, significantly reducing search time.

* Efficient handling of large volumes of text: Full-text indexing effectively processes various types of text data, including articles, reports, web pages, and emails, providing users with precise and fast search experiences.

* Support for complex queries: In addition to basic keyword searches, full-text indexing also supports complex query requirements such as approximate matching and relevance sorting, greatly enhancing the search capabilities of the database.

By incorporating full-text indexing, seekdb significantly improves query performance when dealing with large-scale text data and complex search requirements, allowing users to efficiently retrieve the information they need.

## Efficient search of massive news data using full-text indexing

The following example demonstrates how to use full-text indexing to quickly find the target news in a large amount of information. We will use keywords in the query to show the improvements in functionality, performance, and ease of use of seekdb's full-text indexing.

### Prerequisites

To smoothly operate and experience the full-text indexing feature of seekdb, make sure the following conditions are met:

1. **Environment requirements**: You have deployed seekdb.

2. **Database creation**: Make sure that you have created a database. For more information, see [Create a database](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000002013232).

### Procedure

The following procedure will guide you through the full-text indexing, common views, and query techniques in seekdb.

#### Step 1: Import the dataset

seekdb provides an IK Chinese tokenizer and a Boolean mode that is more efficient than traditional natural language processing. We will use the [Chinese football sports news dataset](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/online-experience/distributed-sql/sports_data_whole.csv) to import data into seekdb. We will create a partitioned table named `sport_data_whole` with three columns of variable-length characters (`event`, `date`, and `news`). We will also create a full-text index for the `news` column using the IK Chinese tokenizer in `max_word` mode.

:::info
The <code>smart</code> mode and <code>max_word</code> mode of the IK tokenizer differ in that the former does not match shorter words after matching the longest word.<br/>seekdb provides other tokenizers, including space and beng for English, and ngram for splitting words by character length.
:::

```sql
-- Create a table and create a full-text index for the news column using the IK tokenizer
CREATE TABLE sport_data_whole (
    event VARCHAR(64),
    date VARCHAR(16),
    news VARCHAR(65535),
    FULLTEXT INDEX ft_idx1_news(news)
        WITH PARSER ik PARSER_PROPERTIES = (ik_mode = "max_word")
);
```

We will import the news dataset to the table by using a local file. The import takes about 6.5 seconds.

```sql
-- Import data
LOAD DATA /*+ PARALLEL(8) */ LOCAL INFILE '/home/admin/sports_data_whole.csv' INTO TABLE sport_data_whole
FIELDS TERMINATED BY ',' LINES TERMINATED BY '\n';
```

After the data is imported, the table contains 100,000 news entries. Each news entry is about 2,700 Chinese characters in length. The original data occupies about 59 MB. After efficient compression, the actual storage space occupied by the data is less than 30 MB. This is mainly because the full-text index contains a large number of inverted and forward index auxiliary tables.

#### Step 2: Query by using the full-text index

We can perform multi-condition searches or highly filtered searches by using the stored news data and the index. For example, as a football fan, if I want to search for news entries that contain both "Bayern" and "own goal", I can use the Boolean mode.

Compared with the string `LIKE` matching without an index, the Boolean mode has a simpler syntax and faster query speed.

```sql
-- Query for news entries that contain both "own goal" and "Bayern" by using the Boolean mode
SELECT COUNT(*) FROM sport_data_whole
WHERE MATCH (news) AGAINST ('+own goal +Bayern' IN BOOLEAN MODE);
```

The result is as follows:

```sql
+----------+
| COUNT(*) |
+----------+
|    14645 |
+----------+
1 row in set (0.03 sec)
```

By contrast, the `LIKE` query is as follows:

```sql
-- Query by using the LIKE syntax
SELECT COUNT(*) FROM sport_data_whole
WHERE news LIKE '%own goal%' AND news LIKE '%Bayern%';
```

The result is as follows:

```sql
+----------+
| COUNT(*) |
+----------+
|    14645 |
+----------+
1 row in set (0.05 sec)
```

We can further rank the two returned news entries based on the scores in the output.

```sql
-- Return the event, date, and score of the news entries to determine their relevance
SELECT event, date, MATCH (news) AGAINST ('own goal Bayern') AS score
FROM sport_data_whole
WHERE MATCH (news) AGAINST ('+own goal +Bayern' IN BOOLEAN MODE) limit 10;
```

The result is as follows:

The Boolean mode also allows us to exclude some keywords. For example, almost every football match has fouls. If I want to know which matches are very intense without any fouls, yellow cards, or red cards, I can use the `-` operator in the Boolean mode.

```sql
-- Query for intense matches without any fouls, yellow cards, or red cards
SELECT COUNT(*) FROM sport_data_whole
WHERE MATCH (news) AGAINST ('+intense -foul -yellow card -red card' IN BOOLEAN MODE);
```


#### Step 3: Tune

##### Optimize with the `TOKENIZE` function

If the query results from a full-text index do not meet your expectations, it is usually because the tokenization results are not ideal. SeekDB provides a quick `TOKENIZE` function to help you test the tokenization effects. This function supports all tokenizers and their corresponding attributes. You can use the `TOKENIZE` function to verify the effectiveness of the tokenizers.

For example, manual tokenization of the sample text below shows that the name dictionary has limited support for foreign sports stars (such as Bautista and Große). This lack of support can lead to poor search results when searching for these individuals by name.

1. Use the `TOKENIZE` function to verify the tokenizer processing effect:

```sql
   -- Verify the word segmentation effect in Chinese sports news using ik_smart mode.
   SELECT TOKENIZE('Boateng drives forward down the right side, then passes the ball forward for Schweinsteiger who fires a shot at the net from eight yards out, and the ball goes into the net before Piato, the keeper, can react', 'ik', '[{"additional_args": [{"ik_mode": "smart"}]}]');
   ```

## MySQL performance comparison

To compare the full-text search performance of seekdb with that of MySQL, we use MySQL's full-text search feature as a reference. Since MySQL has relatively weak Chinese tokenization capabilities, we selected the `wikir1k` dataset (containing 369,721 rows, with an average of 100 words per row) for performance comparison.

The following table shows the comparison results in different scenarios under the natural language mode and the boolean mode. As shown, seekdb outperforms MySQL significantly in scenarios that require extensive tokenization or return a large number of results. For small result sets, since the computational load is relatively low, the advantage of the query engine is not obvious, and the performance of both engines is close.

**Test environment**: seekdb is tested with 8 cores and 16 GB of memory. MySQL 8.0.36 for Linux on x86_64 (MySQL Community Server - GPL) is used.

### Natural language mode

```sql
-- q1: Query documents containing "and".
SELECT * FROM wikir1k WHERE MATCH (document) AGAINST ('and');

-- q2: Query documents containing "and", and limit the result to 10.
SELECT * FROM wikir1k WHERE MATCH (document) AGAINST ('and') LIMIT 10;

-- q3: Query documents containing "librettists".
SELECT * FROM wikir1k WHERE MATCH (document) AGAINST ('librettists');

-- q4: Query documents containing "librettists", and limit the result to 10.
SELECT * FROM wikir1k WHERE MATCH (document) AGAINST ('librettists') LIMIT 10;

-- q5: Query documents containing "alleviating librettists".

-- q6: Query documents containing "black spotted white yellow".

-- q7: Query documents containing "black spotted white yellow", and limit the result to 10.
```

### Performance comparison summary

From the data comparison above, seekdb demonstrates significantly better performance than MySQL in complex full-text searches, whether using natural language mode or Boolean mode. This advantage is particularly evident in queries requiring extensive tokenization or returning a large number of results. This provides developers and data analysts with a strong reference when choosing a database, especially in applications requiring efficient search of large volumes of data. seekdb clearly proves its powerful performance and flexible query capabilities in such scenarios.

seekdb's full-text indexing provides fast response times for complex queries, making it more suitable for real-world applications that require high concurrency and high-performance search.
