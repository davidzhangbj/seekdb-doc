# JSON partial update

seekdb supports JSON partial update. This feature allows you to update only the modified fields in a JSON document without updating the entire document.

## Limitations

## JSON partial update

The JSON partial update feature of seekdb is disabled by default. You can enable or disable the feature by setting the system variable `log_row_value_options`. For more information, see [log_row_value_options](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000003979549).

**Here are some examples:**

* Enable the JSON partial update feature.

  * At the session level:

  ```sql
  SET log_row_value_options="partial_json";
  ```

  * At the global level:

  ```sql
  SET GLOBAL log_row_value_options="partial_json";
  ```

* Disable the JSON partial update feature.

  * At the session level:

  ```sql
  SET log_row_value_options="";
  ```

  * At the global level:

  ```sql
  SET GLOBAL log_row_value_options="";
  ```

* Query the value of `log_row_value_options`.

  ```sql
  SHOW VARIABLES LIKE 'log_row_value_options';
  ```

  The return result is as follows:

  ```sql
  +-----------------------+-------+
  | Variable_name         | Value |
  +-----------------------+-------+
  | log_row_value_options |       |
  +-----------------------+-------+
  1 row in set
  ```

## JSON expressions for partial update

In addition to the JSON partial update feature switch `log_row_value_options`, you must use specific expressions to update a JSON document to trigger JSON partial update.

The following JSON expressions can be used for partial update in seekdb:

* json_set or json_replace: used to update the value of a JSON field.
* json_remove: used to delete a JSON field.

:::tip
  <ol><li>Make sure that the left operand of the <code>SET</code> assignment clause and the first parameter of the JSON expression are the same and are JSON columns in the table. For example, in <code>j = json_replace(j, '$.name', 'ab')</code>, the left operand of the equal sign and the first parameter of the <code>json_replace</code> expression are both <code>j</code>.</li><li>JSON partial update is triggered only when the JSON column is stored in <code>outrow</code> format. The <code>outrow</code> or <code>inrow</code> storage format is controlled by the <code>lob_inrow_threshold</code> parameter during table creation. The <code>lob_inrow_threshold</code> parameter specifies the <code>INROW</code> threshold. If the size of LOB data exceeds this threshold, the data is stored in <code>OUTROW</code> format in the LOB meta table. The default value is 4 KB.</li></ol>
:::

**Here are some examples:**

1. Create a table named `json_test`.

   ```sql
   CREATE TABLE json_test(pk INT PRIMARY KEY, j JSON);
   ```

2. Insert data.

   ```sql
   INSERT INTO json_test VALUES(1, CONCAT('{"name": "John", "content": "', repeat('x',8), '"}'));
   ```

   The return result is as follows:

   ```shell
   Query OK, 1 row affected
   ```

3. Query the data in the JSON column `j`.

   ```sql
   SELECT j FROM json_test;
   ```

   The return result is as follows:

   ```shell
   +-----------------------------------------+
   | j                                       |
   +-----------------------------------------+
   | {"name": "John", "content": "xxxxxxxx"} |
   +-----------------------------------------+
   1 row in set
   ```

4. Use `json_repalce` to update the value of the `name` field in the JSON column.

   ```sql
   UPDATE json_test SET j = json_replace(j, '$.name', 'ab') WHERE pk = 1;
   ```

   The return result is as follows:

   ```shell
   Query OK, 1 row affected
   Rows matched: 1  Changed: 1  Warnings: 0
   ```

5. Query the modified data in the JSON column `j`.

   ```sql
   SELECT j FROM json_test;
   ```

   The return result is as follows:

   ```shell
   +---------------------------------------+
   | j                                     |
   +---------------------------------------+
   | {"name": "ab", "content": "xxxxxxxx"} |
   +---------------------------------------+
   1 row in set
   ```

6. Use `json_set` to update the value of the `name` field in the JSON column.

   ```sql
   UPDATE json_test SET j = json_set(j, '$.name', 'cd') WHERE pk = 1;
   ```

   The return result is as follows:

   ```shell
   Query OK, 1 row affected
   Rows matched: 1  Changed: 1  Warnings: 0
   ```

7. Query the modified data in the JSON column `j`.

   ```sql
   SELECT j FROM json_test;
   ```

   The return result is as follows:

   ```shell
   +---------------------------------------+
   | j                                     |
   +---------------------------------------+
   | {"name": "cd", "content": "xxxxxxxx"} |
   +---------------------------------------+
   1 row in set
   ```

8. Use `json_remove` to delete the value of the `name` field in the JSON column.

   ```sql
   UPDATE json_test SET j = json_remove(j, '$.name') WHERE pk = 1;
   ```

   The return result is as follows:

   ```shell
   Query OK, 1 row affected
   Rows matched: 1  Changed: 1  Warnings: 0
   ```

9. Query the modified data in the JSON column `j`.

   ```sql
   SELECT j FROM json_test;
   ```

   The return result is as follows:

   ```shell
   +-------------------------+
   | j                       |
   +-------------------------+
   | {"content": "xxxxxxxx"} |
   +-------------------------+
   1 row in set
   ```

## Update granularity

seekdb stores JSON data in LOB format. The underlying storage of LOB in seekdb is in blocks. Therefore, the minimum amount of data updated in each partial update is one LOB block. The smaller the LOB block size, the smaller the amount of data written. You can specify the LOB block size when you create a column.

**Here is an example:**

```sql
CREATE TABLE json_test(pk INT PRIMARY KEY, j JSON CHUNK '4k');
```

The chunk size cannot be arbitrarily small. If the chunk size is too small, it will affect the performance of `SELECT`, `INSERT`, and `DELETE`. Generally, we recommend that you set the chunk size based on the average size of JSON fields. If most fields are small, you can set the chunk size to 1 KB. seekdb stores data smaller than 4 KB in `INROW` format for optimized LOB reads. In this case, partial update is not performed. Partial update is mainly used to improve the performance of updating large documents. For small documents, full update performs better.

## Rebuild

JSON Partial Update does not impose any restrictions on the length of the data before and after the update in a JSON column. If the length of the new value is less than or equal to the length of the old value, the new data directly replaces the original data at the same position. If the length of the new value exceeds the length of the old value, the new data is appended to the end. SeekDB sets a threshold: when the length of the appended data exceeds 30% of the original data length, a rebuild is triggered. In this case, instead of performing a partial update, the entire data is overwritten.

You can use the `JSON_STORAGE_SIZE` expression to obtain the actual storage length of the JSON data and the `JSON_STORAGE_FREE` expression to obtain the additional storage overhead.

**Here is an example:**

1. Enable JSON Partial Update.

   ```sql
   SET log_row_value_options = "partial_json";
   ```

2. Create a test table named `json_test`.

   ```sql
   CREATE TABLE json_test(pk INT PRIMARY KEY, j JSON CHUNK '1K');
   ```

3. Insert a row of data into the `json_test` table.

   ```sql
   INSERT INTO json_test VALUES(10 , json_object('name', 'zero', 'age', 100, 'position', 'software engineer', 'profile', repeat('x', 4096), 'like', json_array('a', 'b', 'c'), 'tags', json_array('sql boy', 'football', 'summer', 1), 'money' , json_object('RMB', 10000, 'Dollers', 20000, 'BTC', 100), 'nickname', 'noone'));
   ```

   The return result is as follows:

   ```shell
   Query OK, 1 row affected
   ```

4. Query the storage size of the JSON column (actual occupied storage space) using `JSON_STORAGE_SIZE` and estimate the storage space that can be released using `JSON_STORAGE_FREE`.

   ```sql
   SELECT JSON_STORAGE_SIZE(j), JSON_STORAGE_FREE(j) FROM json_test WHERE pk = 10;
   ```

   The return result is as follows:

   ```shell
   +----------------------+----------------------+
   | JSON_STORAGE_SIZE(j) | JSON_STORAGE_FREE(j) |
   +----------------------+----------------------+
   |                 4335 |                    0 |
   +----------------------+----------------------+
   1 row in set
   ```

   Since no partial update has been performed, the `JSON_STORAGE_FREE` value is 0.

5. Use `json_replace` to update the value of the `position` field in the JSON column. The length of the new value is less than the length of the old value.

   ```sql
   UPDATE json_test SET j = json_replace(j, '$.position', 'software enginee') WHERE pk = 10;
   ```

   The return result is as follows:

   ```shell
   Query OK, 1 row affected
   Rows matched: 1  Changed: 1  Warnings: 0
   ```

6. Query the storage size of the JSON column using `JSON_STORAGE_SIZE` and estimate the storage space that can be released using `JSON_STORAGE_FREE`.

   ```sql
   SELECT JSON_STORAGE_SIZE(j), JSON_STORAGE_FREE(j) FROM json_test WHERE pk = 10;
   ```

   The return result is as follows:

   ```shell
   +----------------------+----------------------+
   | JSON_STORAGE_SIZE(j) | JSON_STORAGE_FREE(j) |
   +----------------------+----------------------+
   |                 4335 |                    1 |
   +----------------------+----------------------+
   1 row in set
   ```

   After the JSON column data is updated, since the new data is one byte shorter than the old data, the `JSON_STORAGE_FREE` result is 1.

7. Use `json_replace` to update the value of the `position` field in the JSON column. The length of the new value is greater than the length of the old value.

   ```sql
   UPDATE json_test SET j = json_replace(j, '$.position', 'software engineera') WHERE pk = 10;
   ```

   The return result is as follows:

   ```shell
   Query OK, 1 row affected
   Rows matched: 1  Changed: 1  Warnings: 0
   ```

8. Query the storage size of the JSON column using `JSON_STORAGE_SIZE` and estimate the storage space that can be released using `JSON_STORAGE_FREE`.

   ```sql
   SELECT JSON_STORAGE_SIZE(j), JSON_STORAGE_FREE(j) FROM json_test WHERE pk = 10;
   ```

   The return result is as follows:

   ```shell
   +----------------------+----------------------+
   | JSON_STORAGE_SIZE(j) | JSON_STORAGE_FREE(j) |
   +----------------------+----------------------+
   |                 4355 |                   19 |
   +----------------------+----------------------+
   1 row in set
   ```

   After the JSON column data is appended and updated, the `JSON_STORAGE_FREE` length is 19, indicating that 19 bytes can be released after the rebuild.
