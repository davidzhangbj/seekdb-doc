# Update of partial data in JSON

SeekDB supports the update of partial data in JSON (JSON Partial Update). This feature allows you to update only the specific fields that need to be modified in a JSON document without having to update the entire document.

## Limitations

## Enable or disable JSON partial update

By default, the JSON partial update feature of OceanBase Database is disabled. You can enable or disable it by setting the system variable `log_row_value_options`. For more information, see [log_row_value_options](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000003979549).

**Here are some examples:**

* Enable the JSON partial update feature.

  * At the session level:

  ```sql
  SET log_row_value_options="partial_json";
  ```

  * At the global level:

  ```sql
  SET GLOBAL log_row_value_options="partial_json";
  ```

* Disable the JSON partial update feature.

  * At the session level:

  ```sql
  SET log_row_value_options="";
  ```

  * At the global level:

  ```sql
  SET GLOBAL log_row_value_options="";
  ```

* Query the value of `log_row_value_options`.

  ```sql
  SHOW VARIABLES LIKE 'log_row_value_options';
  ```

  The returned result is as follows:

  ```sql
  +-----------------------+-------+
  | Variable_name         | Value |
  +-----------------------+-------+
  | log_row_value_options |       |
  +-----------------------+-------+
  1 row in set
  ```

## JSON expressions for partial updates

In addition to the `log_row_value_options` switch for enabling JSON partial update functionality, you must use specific expressions to update the JSON document to trigger the JSON partial update.

The following JSON expressions can be used for partial updates in SeekDB:

* json_set or json_replace: used to update the value of a JSON field.
* json_remove: used to delete a JSON field.

## Granularity of Updates

In SeekDB, JSON data is stored using LOB (Large Object) storage. LOBs in SeekDB are stored in chunks, so each partial update must affect at least one LOB chunk. Smaller chunk sizes result in less data being written during updates. You can specify the chunk size when creating a column using DDL syntax.

**Here's an example:**

```sql
CREATE TABLE json_test(pk INT PRIMARY KEY, j JSON CHUNK '4k');
```

The chunk size cannot be arbitrarily small. Too small a chunk size can negatively impact the performance of `SELECT`, `INSERT`, and `DELETE` operations. Generally, it's recommended to set the chunk size based on the average field size in your JSON documents. If most fields are small, a chunk size of 1K is suitable. SeekDB optimizes LOB reads by storing data smaller than 4K directly in-row (`INROW`), which means partial updates won't occur for such data. Partial updates are primarily designed to improve the performance of updating large documents, while full updates for small documents tend to perform better.

## Rebuild

Json Partial Update does not impose any restrictions on the length of data before and after updates in JSON columns. If the length of the new value is less than or equal to that of the old value, the original data at the specified position is directly replaced with the new data. However, if the length of the new value exceeds that of the old value, the new data is appended to the end. SeekDB has a threshold setting; when the length of the appended data exceeds 30% of the original data length, a rebuild is triggered. In such cases, instead of performing a partial update, the entire data is overwritten.

You can use the `JSON_STORAGE_SIZE` expression to obtain the actual storage size of the JSON column and the `JSON_STORAGE_FREE` expression to estimate the additional storage overhead.

**Here's an example:**

1. Enable JSON Partial Update.

   ```sql
   SET log_row_value_options = "partial_json";
   ```

2. Create a test table named `json_test`.

   ```sql
   CREATE TABLE json_test(pk INT PRIMARY KEY, j JSON CHUNK '1K');
   ```

3. Insert a row of data into the `json_test` table.

   ```sql
   INSERT INTO json_test VALUES(10 , json_object('name', 'zero', 'age', 100, 'position', 'software engineer', 'profile', repeat('x', 4096), 'like', json_array('a', 'b', 'c'), 'tags', json_array('sql boy', 'football', 'summer', 1), 'money' , json_object('RMB', 10000, 'Dollers', 20000, 'BTC', 100), 'nickname', 'noone'));
   ```

   The returned result is as follows:

   ```shell
   Query OK, 1 row affected
   ```

4. Use `JSON_STORAGE_SIZE` to query the storage size of the JSON column (actual occupied storage space) and `JSON_STORAGE_FREE` to estimate the releaseable storage space of the JSON column.

   ```sql
   SELECT JSON_STORAGE_SIZE(j), JSON_STORAGE_FREE(j) FROM json_test WHERE pk = 10;
   ```

   The returned result is as follows:

   ```shell
   +----------------------+----------------------+
   | JSON_STORAGE_SIZE(j) | JSON_STORAGE_FREE(j) |
   +----------------------+----------------------+
   |                 4335 |                    0 |
   +----------------------+----------------------+
   1 row in set
   ```

   Since no partial update has been performed, the value of `JSON_STORAGE_FREE` is 0.

5. Use `json_replace` to update the value of the `position` field in the JSON column. The length of the new value is shorter than that of the old value.

   ```sql
   UPDATE json_test SET j = json_replace(j, '$.position', 'software enginee') WHERE pk = 10;
   ```

   The returned result is as follows:

   ```shell
   Query OK, 1 row affected
   Rows matched: 1  Changed: 1  Warnings: 0
   ```

6. Again, use `JSON_STORAGE_SIZE` to query the storage size of the JSON column and `JSON_STORAGE_FREE` to estimate the releaseable storage space of the JSON column.

   ```sql
   SELECT JSON_STORAGE_SIZE(j), JSON_STORAGE_FREE(j) FROM json_test WHERE pk = 10;
   ```

   The returned result is as follows:

Here is the table showing the storage size and free space of the JSON column:

   ```shell
   +----------------------+----------------------+
   | JSON_STORAGE_SIZE(j) | JSON_STORAGE_FREE(j) |
   +----------------------+----------------------+
   |                 4335 |                    1 |
   +----------------------+----------------------+
   1 row in set
   ```

   After updating the data in the JSON column, since the new data is one byte smaller than the old data, the `JSON_STORAGE_FREE` result is 1.

7. Use the `json_replace` function to update the value of the `position` field in the JSON column with a new value that is longer than the old one.

   ```sql
   UPDATE json_test SET j = json_replace(j, '$.position', 'software engineer') WHERE pk = 10;
   ```

   The returned result is as follows:

   ```shell
   Query OK, 1 row affected
   Rows matched: 1  Changed: 1  Warnings: 0
   ```

8. Query the storage size of the JSON column again using `JSON_STORAGE_SIZE`, and estimate the amount of storage space that can be freed using `JSON_STORAGE_FREE`.

   ```sql
   SELECT JSON_STORAGE_SIZE(j), JSON_STORAGE_FREE(j) FROM json_test WHERE pk = 10;
   ```

   The returned result is as follows:

   ```shell
   +----------------------+----------------------+
   | JSON_STORAGE_SIZE(j) | JSON_STORAGE_FREE(j) |
   +----------------------+----------------------+
   |                 4355 |                   19 |
   +----------------------+----------------------+
   1 row in set
   ```

   After appending new data to the JSON column, the length of `JSON_STORAGE_FREE` is 19, indicating that 19 bytes can be freed after rebuild.
