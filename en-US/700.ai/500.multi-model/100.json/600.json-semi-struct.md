# Semi-structured encoding

This topic describes the semi-structured encoding feature supported by SeekDB.

SeekDB allows you to enable semi-structured encoding when you create a table. The table-level parameter `SEMISTRUCT_PROPERTIES` controls this feature. Additionally, you must set the `ROW_FORMAT` parameter to `COMPRESSED`. Otherwise, an error will occur.

## Considerations

* When `SEMISTRUCT_PROPERTIES=(encoding_type=encoding)`, the table is considered a semi-structured table, meaning that all JSON columns in the entire table will be enabled for semi-structured encoding.
* When `SEMISTRUCT_PROPERTIES=(encoding_type=none)`, the table is considered a structured table.
* Additionally, you can set the frequency threshold using the `freq_threshold` parameter. When semi-structured encoding is enabled, the system analyzes the frequency of each path in the JSON data and stores paths with frequencies exceeding the specified threshold as independent subcolumns, known as frequent columns. For example, if you have a user table where the JSON field stores user information and 90% of users have the `name` and `age` fields, the system will automatically extract `name` and `age` as independent frequent columns. During queries, these columns are accessed directly without parsing the entire JSON, thereby improving query performance.
* Currently, `encoding_type` and `freq_threshold` are supported in Online DDL syntax but not in Offline DDL syntax.

## Data Format

When JSON data is split into structured columns in a specific format, the columns derived from the JSON column are referred to as subcolumns. Subcolumns can be further categorized into sparse columns and frequent columns.

* Sparse Columns: These are subcolumns that exist in some JSON records but not in others, with an occurrence frequency below the threshold specified by the table-level parameter `freq_threshold`.
* Frequent Columns: These are subcolumns that occur in more than the threshold percentage of JSON records specified by the table-level parameter `freq_threshold`. These subcolumns are stored as independent columns to enhance filtering query performance.

Example:

```sql
{"id": 1001, "name": "n1", "nickname": "nn1"}
{"id": 1002, "name": "n2", "nickname": "nn2"}
{"id": 1003, "name": "n3", "nickname": "nn3"}
{"id": 1004, "name": "n4", "nickname": "nn4"}
{"id": 1005, "name": "n5"}
```

In this example, `id` and `name` are fields present in every JSON record, occurring at a frequency of 100%, while `nickname` appears in only 4 out of 5 records, with an occurrence frequency of 80%.

If `freq_threshold` is set to 100%, then `nickname` will be identified as a sparse column, while `id` and `name` will be identified as frequent columns. If `freq_threshold` is set to 80%, then `nickname`, `id`, and `name` will all be identified as frequent columns.

## Examples

1. Enable semistructured encoding

   <main id="notice" type='notice'>
   <h4>Notice</h4>
   <p>Before you enable the semistructured encoding feature, make sure that the value of the <a href="https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000003980046">micro_block_merge_verify_level</a> parameter is set to the default value <code>2</code>, and do not disable micro-block merge verification.</p>
   </main>

   :::tab
   tab Example of enabling semistructured encoding when creating a table

   ```sql
   CREATE TABLE t1(  j json)
   ROW_FORMAT=COMPRESSED
   SEMISTRUCT_PROPERTIES=(encoding_type=encoding, freq_threshold=50);
   ```

   For more information about the syntax, see [CREATE TABLE](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000003980442).

   tab Example of enabling semistructured encoding for an existing table

   ```sql
   CREATE TABLE t1(j json);
   ALTER TABLE t1 SET ROW_FORMAT=COMPRESSED SEMISTRUCT_PROPERTIES = (encoding_type=encoding, freq_threshold=50);
   ```

   For more information about the syntax, see [ALTER TABLE](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000003980488).

   Some limitations:

   * If you modify the frequency threshold without enabling semistructured encoding, no error is returned, but the modification takes effect.
   * During direct load or when a table is locked, you cannot modify the `freq_threshold` parameter.
   * Modifying one subparameter does not affect the other subparameters.
   :::

2. Disable semistructured encoding

   When `SEMISTRUCT_PROPERTIES` is set to `(encoding_type=none)`, semistructured encoding is disabled. This operation does not affect existing data but only applies to subsequent write operations. Here is an example of disabling semistructured encoding:

   ```sql
   ALTER TABLE t1 SET ROW_FORMAT=COMPRESSED SEMISTRUCT_PROPERTIES = (encoding_type=none);
   ```

3. Query the semistructured encoding configuration

   Use the `SHOW CREATE TABLE` statement to query the semistructured encoding configuration. Here is an example:

   ```sql
   SHOW CREATE TABLE t1;
   ```

   The return result is as follows:

   ```shell
   +-------+---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
   | Table | Create Table                                                                                                                                                                                                                                                                                                                                            |
   +-------+---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
   | t1    | CREATE TABLE `t1` (
     `j` json DEFAULT NULL
   ) ORGANIZATION INDEX DEFAULT CHARSET = utf8mb4 ROW_FORMAT = COMPRESSED COMPRESSION = 'zstd_1.3.8' REPLICA_NUM = 1 BLOCK_SIZE = 16384 USE_BLOOM_FILTER = FALSE ENABLE_MACRO_BLOCK_BLOOM_FILTER = FALSE TABLET_SIZE = 134217728 PCTFREE = 0 SEMISTRUCT_PROPERTIES=(ENCODING_TYPE=ENCODING, FREQ_THRESHOLD=50) |
   +-------+---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
   1 row in set
   ```

   When the `SEMISTRUCT_PROPERTIES=(encoding_type=encoding)` option is specified, it indicates that the semi-structured encoding feature has been enabled.

Using semi-structured encoding can improve the performance of conditional filtering queries with the [JSON_VALUE() function](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000003982294). Based on JSON semi-structured encoding technology, SeekDB optimizes the performance of conditional filtering queries using the `JSON_VALUE` expression. Since JSON data is split into subcolumns, the system can directly filter based on the encoded subcolumn data without needing to reconstruct the full JSON structure, significantly enhancing query efficiency.

Here's an example query:

```sql
-- Query rows where the value of the name field is 'Devin'
SELECT * FROM t WHERE JSON_VALUE(j_doc, '$.name' RETURNING CHAR) = 'Devin';
```

Consider the following character set notes:

* SeekDB uses `utf8_bin` encoding for JSON.

* To ensure proper functioning of string whitelisting filters, we recommend setting:

```sql
SET @@collation_server = 'utf8mb4_bin';
SET @@collation_connection='utf8mb4_bin';
```
