# Query and modify JSON values

SeekDB allows you to query and reference JSON values. It also supports extracting parts of a JSON document or modifying specific parts using path expressions.

## Reference JSON values

SeekDB supports two methods for querying and referencing JSON values:

* Use the `-` symbol to reference a key-value pair with double quotes in JSON data.

* Use the `->>` symbol to reference a key-value pair without double quotes in JSON data.

Here are some examples:

```sql
obclient> SELECT c->"$.name" AS name FROM jn WHERE g <= 2;
+---------+
| name    |
+---------+
| "Fred"  |
| "Wilma" |
+---------+
2 rows in set

obclient> SELECT c->>"$.name" AS name FROM jn WHERE g <= 2;
+-------+
| name  |
+-------+
| Fred  |
| Wilma |
+-------+
2 rows in set

obclient> SELECT JSON_UNQUOTE(c->'$.name') AS name
 FROM jn WHERE g <= 2;
+-------+
| name  |
+-------+
| Fred  |
| Wilma |
+-------+
2 rows in set
```

Since JSON files are hierarchical, JSON functions need to use path expressions to extract parts of a JSON document or modify specific content within it. You can also specify the location within the document where the operation should occur.

SeekDB uses the path syntax that starts with a `$` character followed by a selector to indicate the JSON document being accessed. The types of selectors are as follows:

* The `.` symbol indicates the name of the key to access. Unquoted names in path expressions are invalid (for example, spaces), so you must specify the key name in double quotes.

  Here is an example:

  ```sql
  obclient> SELECT JSON_EXTRACT('{"id": 14, "name": "Aztalan"}', '$.name');
  +---------------------------------------------------------+
  | JSON_EXTRACT('{"id": 14, "name": "Aztalan"}', '$.name') |
  +---------------------------------------------------------+
  | "Aztalan"                                               |
  +---------------------------------------------------------+
  1 row in set
  ```

* The `[N]` symbol placed after the path of the selected array indicates the value at position N in the array, where N is a non-negative integer. Array positions are zero-based. If the `path` does not select an array value, then `path[0]` has the same computed value as `path`.

  Here is an example:

  ```sql
  obclient> SELECT JSON_SET('"x"', '$[0]', 'a');
  +------------------------------+
  | JSON_SET('"x"', '$[0]', 'a') |
  +------------------------------+
  | "a"                          |
  +------------------------------+
  1 row in set
  ```

* The `[M to N]` symbol specifies a subset or range of array values, starting from the value at position M and ending at the value at position N.

  Here is an example:

  ```sql
  obclient> SELECT JSON_EXTRACT('[1, 2, 3, 4, 5]', '$[1 to 3]');
  +----------------------------------------------+
  | JSON_EXTRACT('[1, 2, 3, 4, 5]', '$[1 to 3]') |
  +----------------------------------------------+
  | [2, 3, 4]                                    |
  +----------------------------------------------+
  1 row in set
  ```

Path expressions can also contain the * or ** wildcard characters. The following table describes these wildcards:

  * `.[*]` represents the values of all members in a JSON object.

  * `[*]` represents the values of all elements in a JSON array.

  * `prefix**suffix` represents all paths that start with a named prefix and end with a named suffix. The prefix is optional, but the suffix is required. You cannot use ** or *** to describe any path.

    <h4>Note</h4>
    <p>A path that does not exist in a document (i.e., data that does not exist) is calculated as <code>NULL</code>. </p>
  </main>

## Modify JSON values

SeekDB also allows you to modify the complete JSON value by using DML statements, and to use the JSON_SET(), JSON_REPLACE(), or JSON_REMOVE() function in an `UPDATE` statement to modify partial JSON values.

Here are some examples:

```sql
// Insert all data.
INSERT INTO json_tab(json_info) VALUES ('[1, {"a": "b"}, [2, "qwe"]]');

// Insert partial data.
UPDATE json_tab SET json_info=JSON_ARRAY_APPEND(json_info, '$', 2) WHERE id=1;

// Update all data.
UPDATE json_tab SET json_info='[1, {"a": "b"}]';

// Update partial data.
UPDATE json_tab SET json_info=JSON_REPLACE(json_info, '$[2]', 'aaa') WHERE id=1;

// Delete partial data.
DELETE FROM json_tab WHERE id=1;

// Update partial data by using a function.
UPDATE json_tab SET json_info=JSON_REMOVE(json_info, '$[2]') WHERE id=1;
```

## JSON path syntax

A path consists of a scope and one or more path segments. For paths used in JSON functions, the scope is the document that is being searched for or otherwise manipulated. The scope is indicated by the leading $ character.

Path segments are separated by periods (.). Elements in an array are indicated by \[N\], where N is a nonnegative integer. Key names must be either double-quoted strings or valid ECMAScript identifiers.

Path expressions (such as JSON text) should be encoded with the ascii, utf8, or utf8mb4 character set. Other character sets are implicitly converted to utf8mb4.

The full syntax is as follows:

```sql
pathExpression: // Path expression
    scope[(pathLeg)*]   // Scope is indicated by the leading $ character

pathLeg:
    member | arrayLocation | doubleAsterisk

member:
    period ( keyName | asterisk )

arrayLocation:
    leftBracket ( nonNegativeInteger | asterisk ) rightBracket

keyName:
    ESIdentifier | doubleQuotedString

doubleAsterisk:
    '**'

period:
    '.'

asterisk:
    '*'

leftBracket:
    '['

rightBracket:
    ']'
```
