# CHAR and VARCHAR

The `CHAR` and `VARCHAR` types are similar, but they differ in storage and retrieval methods, maximum length, and whether trailing spaces are preserved.

## CHAR

The `CHAR` type specifies the maximum number of characters that can be stored. For example, `CHAR(30)` indicates that up to 30 characters can be stored.

The syntax is as follows:

```sql
[NATIONAL] CHAR[(M)] [CHARACTER SET charset_name] [COLLATE collation_name]
```

Use `CHARACTER SET` to specify the character set. You can also use the `COLLATE` attribute and other attributes to specify the collation for the character set. If you specify the binary attribute of `CHARACTER SET`, the column is created as a corresponding binary string data type, and `CHAR` becomes `BINARY`.

The length of a `CHAR` column can be any value between 0 and 256. When storing values of the `CHAR` type, trailing spaces are added on the right to fill the specified length.

For a `CHAR` column, regardless of the SQL mode, trailing spaces in inserted values are silently truncated. When retrieving values from a `CHAR` column, if the `PAD_CHAR_TO_FULL_LENGTH` SQL mode is not enabled, trailing spaces are removed.

## VARCHAR

The `VARCHAR` type specifies the maximum number of characters that can be stored. For example, `VARCHAR(50)` indicates that up to 50 characters can be stored.

The syntax is as follows:

```sql
[NATIONAL] VARCHAR(M) [CHARACTER SET charset_name] [COLLATE collation_name]
```

Use `CHARACTER SET` to specify the character set. You can also use the `COLLATE` attribute and other attributes to specify the collation for the character set. If you specify the binary attribute of `CHARACTER SET`, the column is created as a corresponding binary string data type, and `VARCHAR` becomes `VARBINARY`.

The length of a `VARCHAR` column can be any value between 0 and 262144.

Unlike `CHAR`, values of the `VARCHAR` type are stored with a 1-byte or 2-byte prefix indicating the number of bytes in the value. If the value contains fewer than 255 bytes, the prefix occupies one byte. If the value may contain more than 255 bytes, the prefix occupies two bytes.

For a `VARCHAR` column, regardless of the SQL mode, trailing spaces exceeding the column length are truncated before insertion and generate an alert.

When storing values of the `VARCHAR` type, trailing spaces are not padded. According to standard SQL, trailing spaces are preserved during storage and retrieval.

Additionally, SeekDB supports the extended type `CHARACTER VARYING(m)`, but it is recommended to use `VARCHAR(m)`.
