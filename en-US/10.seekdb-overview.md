# Get started with SeekDB

OceanBase SeekDB (short for SeekDB) is a new generation of database products developed by OceanBase, focusing on providing efficient hybrid search capabilities for AI applications. It supports unified storage and retrieval of vector, full-text, and multimodal data. As a key component of the OceanBase product family, SeekDB inherits the high-performance advantages of the original core engine and the comprehensive compatibility with MySQL. By deeply optimizing the data search architecture, SeekDB provides developers with solutions that better meet the needs of AI data processing.

## Architecture

![seekdb-arch](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/SeekDB/overview/seekdb-arch.png)

* Storage layer: A row-column hybrid storage engine based on the LSM-tree architecture, with a self-developed efficient encoding and compression mechanism to reduce storage costs. It supports high-frequency real-time data writing and high-performance queries for different workloads. It supports the storage of basic types, multimodal types, and vector types, and provides efficient indexing support.

* Compute layer: Supports vector, full-text, and scalar hybrid search. It provides an advanced query optimizer and a high-performance execution engine with vectorized execution capabilities. It also supports complete ACID transactions and multi-version concurrency control (MVCC) for concurrent access. These features ensure stable support for various business requests.

* Interface layer: It is compatible with MySQL native drivers and provides more user-friendly vector library and hybrid search access interfaces, such as the pyobvector SDK and obvec_jdbc SDK.

* Application framework layer: It is compatible with nearly 30 application development frameworks, including AI application development frameworks such as LangChain, LlamaIndex, and Dify. It provides the MCP Server for seamless integration with the AI ecosystem. It supports two deployment modes: client/server and embedded.

## Core features

### Minimal deployment, instant initialization

The single-node architecture allows for instant initialization without complex configurations. It supports both Client/Server and embedded deployment modes. In the Client/Server mode, it can be deployed using yum install, Docker, or desktop versions for Windows and macOS. In the embedded mode, it integrates natively with Python and can serve as an embedded database within AI applications.

### Minimum 1C1G specifications, vertical scalability

With a minimum of 1 CPU core and 1 GB of memory, it can be quickly started for trial use. For vector search and hybrid search scenarios, it is recommended to have at least 4 GB of memory. When high requirements are placed on system concurrency, data volume, and query complexity, resources can be flexibly scaled vertically.

### High-performance vector and full-text indexes, hybrid search

* Vector search

	Supports storage and retrieval of up to 16,000-dimensional vectors with high performance. It is compatible with various distance calculation methods, including L2, inner product, and cosine similarity. It provides HNSW and IVF indexes along with related quantization algorithms, supporting approximate nearest neighbor search to meet semantic retrieval needs in AI scenarios.

* Full-text search

	Offers high-performance full-text indexing based on the BM25 relevance ranking algorithm for precise keyword searches. It supports multiple tokenizers such as Space, Beng, Ngram, IK, and Jieba. It provides various query modes, including Natural Language Mode, Boolean Mode, Phrase Query, and Multi Match, enabling quick information retrieval from large volumes of text data and improving query efficiency.

* Hybrid search

	Supports hybrid search across vector, full-text, scalar, and spatial data types, allowing multiple queries and re-ranking to be completed with a single SQL statement.

SeekDB also provides the Hybrid Index feature. By simply writing text data, the system automatically generates embeddings and vector indexes. During queries, specifying text search conditions is sufficient for semantic search. This feature meets the needs of hybrid data queries in RAG solutions, helping enterprises build efficient and intelligent data retrieval systems.

Supports SQL, Python SDK, and Java SDK for various application development environments.

### Seamless integration with various models, built-in AI functions for real-time inference

SeekDB supports the integration of chat models and embedding models. It provides the DBMS_AI_SERVICE system package for managing AI model information. It includes built-in AI functions such as AI_COMPLETE, AI_EMBED, and AI_RERANK, enabling AI data processing and real-time inference within the database using SQL expressions.

### Dynamic schema based on JSON, supporting dynamic storage and efficient access of document metadata

SeekDB supports the JSON data type and offers dynamic schema capabilities. It allows for partial JSON updates to reduce data update costs and provides JSON function indexes and multi-value indexes to optimize query performance. It supports semi-structured encoding to lower storage costs. In AI applications, JSON can serve as a storage type for document metadata and supports hybrid search capabilities with full-text and vector data.

### Real-time data writing and querying

Based on the LSM-Tree storage architecture, SeekDB supports high-frequency real-time data writing. During data DML operations, it synchronously builds various indexes, including full-text, vector, and scalar indexes, allowing for immediate querying after data is successfully stored.

### Compatibility beyond MySQL, supporting HTAP hybrid workloads

SeekDB is highly compatible with MySQL in terms of syntax, protocols, and views but offers more extensive support for computing and storage engines across various scenarios. Leveraging row-column hybrid storage technology and vectorized execution capabilities, a single instance can simultaneously support online transaction processing (OLTP) and real-time analytics, eliminating the need for data synchronization and reducing maintenance costs.

## FAQs

* Q: What are the differences between SeekDB and OceanBase Database Standalone?

	A: OceanBase Database Standalone is a single-node database product that includes all the features of the distributed version and is suitable for non-core or small-scale businesses. It provides a smooth transition to the distributed version. SeekDB is a new database product designed for the ecosystem, with a lower entry barrier. It removes complex features such as multi-tenancy, distributed processing, and Oracle compatibility, and focuses on rapid iteration of DB4AI capabilities in MySQL-compatible mode.

* Q: Can I upgrade from SeekDB to OceanBase Database?

	A: Direct upgrades are not supported, but you can perform a logical migration from SeekDB to OceanBase Database.

* Q: What are the evolution strategies of SeekDB and OceanBase Database?

	A: SeekDB is based on OceanBase Database V4.3.5 and includes most of its features. Currently, both products will evolve separately. AI-related features can be iterated more quickly in SeekDB, and eventually, they will also be supported in OceanBase Database.
